## 結論

- 既有 `food_places` 結構足夠承載新候選，無需 migration、無新服務。
- 去重＝「先查再插／先比再寫」（應用層守門），**無原子去重保證**；併發下同 ID 雙 INSERT 以 PK 唯一約束擋第二者（報錯，非靜默合併），同值雙 UPDATE 會各產生版本＋稽核，需人工核對。
- 測試分支成功≠正式可用；正式 INSERT／更新需使用者授權（見 `CHAT_ACCEPT.md` 5b 影響說明）。
